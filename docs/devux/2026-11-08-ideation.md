# Developer UX review: ideation (2026-11-08)

**Question:** what does Nacre need to improve the first phase of work, from a loose idea (or "something's off")
to a bead or an approved OpenSpec change, compared with what the Claude Code and Codex apps give in that phase?

**Answer.** Nacre's back half is ahead of both apps. Intake gives a verdict that cites its sources,
approval is bound to an exact revision, and Needs you is a phone-first queue. The front half has three
problems:

1. **The brainstorming flow the specs describe is gone from the app.** Commit 6134903 ("remove what chat
   replaced") deleted the New effort entry point and the sheet that Continue opened. Nothing calls
   `startNewEffort` anymore, so the drafting prompt is never sent. In the chat-first Chat, the Draft card has
   no button. To move an idea forward, you have to know to type "go ahead". The accepted specs still promise
   New effort → Continue → sheet.
2. **The tools the agent uses to think with you never reach the phone in a usable form.** Claude's
   multiple-choice questions (AskUserQuestion) and its plan approval (ExitPlanMode) become a generic
   "Claude asks to use AskUserQuestion · Allow / Deny" card. You can't see the question, and Allow sends no
   answer back. A quick answer's plan runs without you approving it. Codex's questions are rejected
   outright. These are the core of how both desktop apps handle brainstorming and ambiguity.
3. **What you settle in the brainstorm doesn't survive the handoff.** The author and reviewer never see
   the chat. The note you type on the intake card is dropped. Each revision's feedback overwrites the one
   before it. The approve card can't show whether what you insisted on made it in.

The fix is not a new screen. It is to make the brainstorm a first-class mode in Chat with a visible way
forward, let the agent's questions and plans arrive as real cards, and carry a digest of the brainstorm into
the bead the author reads.

## What Nacre already does well here (keep it)

- Intake checks a new idea against the accepted specs and active changes before any work, cites its basis,
  and lets you override it. Neither desktop app does this.
- Decision cards with "Ask about this" (explains, never answers) and "In my own words", plus Needs you's
  in-order walkthrough, are a calmer place to recover from confusion than plain chat.
- Inline mockups (0.42.0) and the tabletop layout (conversation above the fold, composer below) suit
  sketching options.
- The "On screen" note means "this" always resolves to what you're looking at.
- Protected actions still go only through cards you answer, so none of the proposals below loosen that.

## Now, Next, Later

### Now: make the brainstorm a mode with a way out (first slice below)

- **Bring back New effort and give the Draft card its action (#1).** Add New effort as a primary action in
  the Chats drawer and the empty-project state, wired to the existing `startNewEffort`. The latest Draft
  card gets **Where does this belong?**, which raises intake *from that recorded draft event*, so what you
  read is what gets filed. It also gets "Or tell the chat what to change." Update `DraftingPrompt`
  (`drafts.go:37` still describes the deleted sheet) and the two specs.
  Evidence: `ChatPane.kt:233`, `Conversation.kt:109,129`, `ChatHub.kt:392,405`, `turn.go:149`, spec
  agent-chat / New effort drafts in Chat, spec effort-intake / New effort runs intake.
- **Brainstorm mode in practice (#7, #3).** A New effort chat runs on your model, not the light route, in
  plan permission mode, with writes allowed only under `$NACRE_MOCKUPS_DIR`. Before the first draft, the agent
  restates what it thinks you mean in two lines, names its assumptions, and asks at most three *numbered*
  questions, so "2: per chat" is a full answer. Each new draft says in one line what changed. It raises
  intake only on your go-ahead or the button: `briefing.go:54` currently contradicts `:71`.
  Evidence: `route.go:58`, `turn.go:333`, `claude/chat.go:54`, `drafts.go:35`.
- **Carry the brainstorm into the bead (#5, #2, #14).**
  - When intake is raised, the chat writes a short digest (decided, ruled out, open questions, mockups,
    chat id). nacred posts it as the seed bead's first comment before developing. The author already
    reads `seed_comments` as owner decisions, so this needs no new channel.
  - Set `NoteField` on intake's create and develop actions.
  - Append each revision's feedback as a seed comment instead of overwriting `r.Feedback`.
  Evidence: `author.go:41,69-76`, `decision_intake.go:131-167`, `decisions.go:626-643`, `manager.go:632`.
- **Copy pass on the cards (#4, part of #10).** Change these strings:
  - "Intake says: New change" / "Intake cost $0.04…" becomes "Suggested: New change, because …" /
    "Nothing happens until you pick one". Cost moves into an expandable detail.
  - New change becomes "Files it, then writes and reviews a proposal for you to approve".
  - Approve's "Not right…" becomes "Send back for changes…".
  - "Freezes the plan at revision 1a2b3c4" becomes "Locks in this version of the plan".
  - "Handed to the full harness" becomes "Switching to the full agent so it can …".

  Evidence: `decision_intake.go:172,212,216-218`, `decision_build.go:227,258,267`,
  `DecisionCard.kt:269`, `ChatTranscript.kt:74`.

### Next: let the agent think with you on the phone

- **AskUserQuestion becomes a question card, and ExitPlanMode becomes a plan card (#6).** Catch them in
  nacred's control handler (`permissions.go:86`):
  - Questions use the existing question-card pattern (choices with details, In my own words, Ask about
    this). The picks go back as `updatedInput.answers`.
  - The plan card renders the full plan with Go ahead, Keep planning… and Make it a draft. Only Go ahead
    starts the full turn, and that applies to light-turn plans too (`turn.go:502`).
  - Codex's `request_user_input` maps to the same card (`codex.go:96`).
  - Unanswered questions stay in Needs you instead of being denied after 15 minutes, so the walkthrough
    takes you through brainstorm questions alongside approvals. Neither desktop app has a queue like that.
- **Decision state on the draft (#8, #15).** Add optional `decided`, `open_questions` and `out_of_scope`
  fields to `nacre-draft`. The card header says "2 open". Each new draft gets "Changed: acceptance,
  design" markers, and earlier drafts collapse to a line with "Use this one".
- **Replies, not status chips (#9).** The agent may end a reply with up to three candidate answers (a
  `nacre-replies` block, stripped the way drafts are). They become the composer suggestions, and picking
  one only fills the composer.
- **Card answers reach the chat (#11).** When you answer a card the chat raised, one line goes into that
  chat's next note, for example "Ryder answered the intake card: Dropped it: 'I meant per project'".
- **Ask about this on every card (#16).** It opens the chat that raised the card, prefilled with "What
  does this card mean, and what happens with each choice?", and quotes the options too.
- **"Something's off" triage (#12).** A briefing section: diagnose read-only first, then say whether the
  code disagrees with a cited requirement, the spec is silent, or the spec is wrong. Then draft it as a bug
  or feature with the citation.

### Later

- **Coming back (#13):** retitle a chat from its latest draft title; show "Idea · not filed" on drawer
  cards; let an intake card wait for its draft instead of expiring; offer "Where did we leave this?" on a
  chat that has been idle for a while and has a draft.
- **Park it (#17):** a Draft card action that raises intake with Just a bead recommended, for capturing an
  idea in 20 seconds.
- **Sign-off traces back (#18, #19):** "From your draft" on the approve card marks each acceptance line as
  covered or not found, plus "Open the chat it came from". Say plainly when the author overrode your intake
  pick. Add "Changes since your last review" on revised proposals.
- **Alternatives (#20):** "Branch from here" (`--fork-session`) to try direction B in a sibling thread;
  a narrow `nacre.reply(text)` bridge in mockups that only fills the composer; a question card whose options
  each carry a mockup, shown side by side when unfolded.
- **Confusion polish:** pass every error through `friendly()` and add Try again; when a draft can't be read,
  send the parse error back to the agent once; give the Stale and Stopped banners a "What now?" action.
- **Repositories without OpenSpec:** the briefing still sends all new work to intake there. Either answer
  intake with Just a bead only, or let the chat create the bead after a yes.

## First slice

**OpenSpec change `brainstorm-in-chat`** covers gaps #1, #2, #3, #5, #7 and #14, plus the card copy in #4.

- **Why:** the specified way from an idea to intake was removed with the old shell, so a Draft card is a
  dead end. What you settle in the brainstorm doesn't reach the proposal's author.
- **What changes:**
  - New effort comes back in Chat, and the Draft card gets "Where does this belong?" (intake from the
    recorded draft).
  - New effort chats run on the owner's model in plan mode, with mockup writes only.
  - The drafting prompt asks the agent to restate the idea and number its questions, and intake runs only
    on a go-ahead.
  - A brainstorm digest becomes the seed bead's first comment.
  - Intake notes are kept.
  - Revision feedback is appended, not overwritten.
  - The intake and approve card copy loses jargon and dollar amounts.
- Light and New effort turns may write mockups, and the briefing suggests Mermaid for flows (V1, V2).
- **Specs modified:** agent-chat (New effort drafts in Chat), effort-intake (New effort runs intake; Ryder
  confirms or overrides), spec-guided-work (author inputs).
- **Size:** about one nacred change (routing, drafting prompt, intake actions, seed comment, feedback log)
  and one app change (entry point, Draft card button, copy). It needs no new destination.

The **second slice** (`agent-questions-on-the-phone`) is the Next item for AskUserQuestion, ExitPlanMode
and Codex questions. It is the one that most changes how Nacre feels against the desktop apps.

## Not recommended

- **Bringing back the deleted New effort sheet.** The chat-first direction is right. Intake as a card in
  the thread works, and the gap is only the missing button.
- **A separate Brainstorm tab or destination.** It goes against Chat as the centre. Brainstorming should
  be a chat mode with a visible state.
- **Letting the chat `bd create` new work without intake** (raised for fast capture). It skips the one
  check neither desktop app has. "Park it" should still raise intake, with Just a bead recommended.
- **Removing cost entirely.** Keep it as an expandable detail, never on buttons or in the headline.
- **Best-of-N parallel drafting for every effort.** It's expensive for a solo owner, and branch-on-demand
  covers the need.

## Method

- **Lenses:** benchmark, persona journeys (five), convergence and sign-off, confusion recovery, and Codex
  as a second harness. Each read the brief (`docs/devux/briefs/2026-11-08-ideation.md`), the rubric and its
  lens, then the code and specs. All five independently found the removed New effort path or the flattened
  agent questions.
- **Verified by hand:**
  - nothing calls `startNewEffort`;
  - `ChatPane.kt:233` passes no `onContinue`;
  - `permissions.go:86` makes every tool request a generic permission;
  - `AllowControl` returns the input unchanged;
  - the router sends New effort talk to light;
  - `decision_intake.go` has no `NoteField`;
  - `manager.go:632` overwrites feedback;
  - nothing in `notes.go` tells the chat about card answers;
  - the dollar and "Not right" strings.
- **Visual thinking lens:** run afterwards on its own. Verified the fixed frame heights, zoom and DOM
  storage off in `MockupCard.kt`, the `NACRE_MOCKUPS_DIR` name, and that nothing reads `dependsOn`.
- **Not checked on a device.** No decision card was answered. The behaviour in repositories without
  OpenSpec, and the AskUserQuestion card text on screen, come from reading the code.
- **Rerun:** `/devux-review ideation` after the first slice lands, or `/devux-review return` for the
  coming-back journey in depth.
