# Design

## Context
`ChatFab` sits in each screen's FAB column (Board, Bead detail, Repos/Multi). It opens a menu of chat slots, and opening a slot shows `ChatWindow`. For Board and Multi chats that is `AssistantPane` inside a `Dialog`, which is the floating drawer. For Bead chats it is `BeadChatSheet`, which is already a `HandleDismissSheet`. Conversations live in `container.chatStack`, keyed by `ChatContext`.

Board and Runs already decide on a side pane with `maxWidth >= 760.dp`. The board shows a right-side `BeadDetail(inPane = true)` pane. Its width comes from `rememberPaneWidth(rootBounds, maxWidth, prefs.detailPaneDp ?: 440)`, which also takes the hinge into account. Back closes that pane first (`BackHandler(canPane && pane != null)`). Existing panes (BeadDetail, RunDetail, AssistantPane when `inPane`) use `surfaceContainerLow` with no window insets.

## Decisions
- **Wide check.** Move the 760.dp threshold into one shared function, `isPaneWide(maxWidth)`, in `ui/common`. Board `canPane`, Runs `wide` and the chat host all use it. The value doesn't change and no breakpoint is added.
- **Pane width and style.** Move `rememberPaneWidth` into `ui/common` unchanged and use it for the chat pane too, so the chat pane has the same (resizable) width and hinge behavior as the bead pane. The chat pane uses the existing pane style: `surfaceContainerLow`, no window insets, no `shadowElevation`, no rounded card. It is separated from the body the same way the bead pane is.
- **Shared content.** `BeadChatContent` is pulled out of `BeadChatSheet`: the messages, input and develop affordance, without the sheet wrapper. `BeadChatSheet` keeps wrapping it, so phone behavior is unchanged. Board and Multi chats use `AssistantPane(inPane = true)`. `ChatContent(selected)` picks between the two. The pane and the sheet both render `ChatContent`.
- **View state.** A `ChatViewState(draft: String, firstVisibleIndex: Int, firstVisibleOffset: Int)` is held in `chatStack` for each chat and read and written by both content composables. Collapsing, swapping or moving between pane and sheet therefore keeps the draft and the scroll position. The state is dropped when the chat is dismissed or expires.
- **Per-screen presentation.** `chatStack` holds `ChatPresentation(selected: ChatContext?, collapsed: Boolean)` keyed by the screen's own context (`Board(repo)`, `Bead(repo,id)`, `Multi`). `selected` can be any chat in the stack, for example a bead chat picked from the board menu. Navigating away disposes the host, so other screens show nothing. Coming back reads the screen's presentation again. Following a bead or run link from inside a chat navigates without clearing the presentation. Dismissing the sheet or tapping Close clears the presentation, but the chat stays in the header list.
- **Layout decision.** A pure function `chatLayout(isWide, available, paneWidth, minBody = 360.dp, presentation, beadPaneOpen): ChatLayout` returns one of `None`, `Docked`, `EdgeTab` or `Sheet`. There is no dialog value. When the window is wide but `available - paneWidth < minBody`, it returns `Sheet`. A collapsed presentation on a narrow window returns `None`, and the chat stays reachable from the header.
- **Header entry point.** `ChatHeaderAction(screenContext, label, onSelect, …)` goes in each screen's top app bar `actions`. It shows the AI icon with an active-chat count badge and a dropdown with the current rows ("New · <label>", active chats, dismiss). Choosing a row sets that screen's `selected` and expands the pane. `ChatFab` and `ChatWindow` are deleted in the same section that adds the host.
- **Board's one pane slot.** The board's right side shows one pane at a time: the bead detail or the chat. Opening a chat while a bead is in the pane shows the chat, and the bead id is remembered. Closing or collapsing the chat brings that bead back. Tapping a bead card while a chat is docked shows the bead and leaves the chat as the edge tab. The edge tab (40.dp, AI icon plus a vertical label) sits at the far right edge, outside the slot, so it is visible next to the bead pane as well.
- **Embedded bead detail.** When `BeadDetail(inPane = true)` is inside the board's pane, its header chat action opens the bead chat through a callback in the board's host. The chat becomes the board screen's `selected` and swaps into the slot as described above. The embedded bead detail never creates its own host. The full-screen `BeadDetail` has its own host keyed by `Bead(repo,id)`.
- **Back.** Back handlers are applied in this order: (1) an expanded docked chat collapses to the edge tab; (2) the board's bead pane closes, as today; (3) normal navigation. On a phone, Back dismisses the sheet, which closes the view as above.
- **Expiry.** When a chat expires (`stack.contains(selected)` turns false), the host clears the presentation and the view state and shows nothing, as `ChatWindow` does today. Nothing is sent into the expired session.
- **Fold or rotate.** If the width crosses the threshold, the same chat moves between pane and sheet with its view state. A collapsed pane that becomes narrow is shown as closed.

## Risks
- Keyboard and IME on the cover screen: the sheet keeps the input reachable, as `spec-guided-work` requires, by keeping `BeadChatSheet` and `HandleDismissSheet` behavior.
- Scroll restore: list position is stored as an index and offset, so a list that grew while collapsed restores to the same item, not the same pixel.
